# 🚄 票路 · 车票路径规划器

> **直达没票？换条路走。**
>
> 基于 12306 实时数据的多策略购票方案规划工具 —— 帮你把「买长乘短 / 买短乘长 / 中转换乘 / 同车换乘」这些野路子，一次性算清楚。

**在线体验**：<https://piaolu.cc.cd>

---

## 这个工具解决什么问题

12306 只告诉你「这趟车有没有票」，但没告诉你：

- 买到**更远的站**，反而有票，中途下车就行
- 目标区间没票，但**分成两段买**能走
- 直达没票，**换个枢纽换乘**能到
- 同一趟车**拆成两段**买（中途不下车），也许两段都有票

这个工具把这些思路全部自动化：一次查询，同时给出直达、候补、买长乘短、中转换乘、同车换乘、买短乘长六种方案，并标出**哪个最便宜、哪个最快、哪个到得最早**。

## ✨ 核心能力

### 六种购票策略

| 策略 | 思路 | 自动化程度 |
|---|---|---|
| 🚄 直达（有票） | 直接查目标区间 | 自动 |
| ⏳ 直达（可候补） | 无票车次可提交候补 | 自动识别 |
| 🎯 买长乘短 | 买到更远站，在目标站提前下车 | 自动枚举更远站点并查余票 |
| 🔄 中转换乘 | 经枢纽站换乘，两段自由搭配 | 自动查 20~30 个枢纽 + 可衔接性筛选 |
| ✂️ 同车换乘 | 同一趟车分段购票，中途不下车 | 自动枚举中间站并校验两段余票 |
| 📝 买短乘长 | 先买短途票上车，再补票到终点 | 自动枚举中间站 |

### 💰 真实票价，不是估算

票价直接来自 12306 的实时数据，不是按里程或倍率估出来的。

- 商务座、一等座、二等座、软卧、硬卧、硬座、无座，每种席别都显示实际价格
- 鼠标悬停，能看到这趟车所有席别的票价
- 实在拿不到票价的车次，会退回估算并标上 `≈`，不冒充真实价
- 实测京沪线 54 趟车，**全部显示真实票价**

### 🏙️ 市内出发：一个城市，所有车站一起查

选了「温州南」，温州、温州北、瑞安、乐清、苍南…… 这个城市的所有车站会一起查。
不用再担心"这个站没票，隔壁站其实有票"。

温州南 → 上海虹桥 实测：

| 查询方式 | 车次 |
|---|---|
| 只查温州南 | 101 趟 |
| 开启市内出发 | **150 趟** |

多出来的 49 趟来自苍南、平阳、瑞安、雁荡山、乐清 —— 不开这个选项，你根本看不到这些票。

全国城市都适用。北京、广州、成都这类高铁站多的城市收益最大（北京 65 个站、广州 45 个、成都 36 个）。

- 大站优先，最多合并 8 个车站
- 只作用于直达列表；买长乘短、同车换乘、买短乘长 查的是特定车次，不受影响，也不会因此变慢

### 🌙 跨日换乘

跨日换乘会查出发日 / 次日 / 第三日三天。同一趟车三天都会出现（时刻相同、日期不同），所以在第二段发车时间前标出 **`+1` / `+2`** 徽标：

```
Z218  +0  03:34 → 16:42
Z218  +1  03:34 → 16:42
Z218  +2  03:34 → 16:42
```

换乘间隔和总耗时都会把跨日算进去 —— 第一段跨夜、第二段第二天才走，也不会显示成负数或 0 分钟。

### 🏅 中转最优标签（可点击）

每个枢纽标题旁自动标注，且**点击即选中对应车次**：

```
🔄 经 天津南 换乘  [价格最低] [到达最快]      9趟前程 + 24趟后程
🔄 经 南京南 换乘  [时间最短]                52趟前程 + 20趟后程
```

| 标签 | 意思 |
|---|---|
| 💰 价格最低 | 这条换乘线路，两段加起来最便宜 |
| ⏱️ 时间最短 | 从上车到下车，全程耗时最短（含换乘等待） |
| 🏁 到达最快 | 到达时间最早，跨日也算进去 |

- 只算真正买得到的方案（两段都有票），不会把"最低价"标在一张买不到的票上
- 点一下标签，对应的两段车次自动选中，底部直接显示总耗时、总花费
- 三个标签可以来回切换比较，当前查看的那个会高亮

### 📊 排序与筛选

每个策略卡片独立排序、独立筛选：

- 排序：出发时间 / 到达时间 / 耗时 / 价格（再点一次反向）
- 筛选：出发时间范围、到达时间范围，支持跨零点（22:00 ~ 06:00）
- 六种策略类型全部支持（中转换乘按「枢纽块最优组合」排序，同车换乘按车次排序）

### 🔎 阅读设置（右上角）

字号可在 **16~24px** 之间无级调节（每格 1px，默认 18px），拖动即时生效，刷新后保留。

旁边还有 **老年人模式**：开启后字号直接拉到 26px（超出滑块上限），并同步放大行距、间距、勾选框，加深文字对比度，车次列表改为单列、隐藏时间筛选等次要元素。开启时字号滑块会变灰锁定，关闭后自动回到你之前设定的字号。

### ▤ 单列 / 双列（左上角）

车次列表可在单列（默认）与双列之间切换，选择会被记住：

- **单列**：整列 1080px，信息舒展，适合慢慢看
- **双列**：容器放宽到 1460px，一屏看两倍车次，适合快速筛选

窄屏（≤899px）与老年人模式下自动锁定单列。

## 🚀 快速开始

### 在线访问

直接打开 <https://piaolu.cc.cd>

### 本地运行

```bash
git clone https://github.com/clq12/train-planner.git
cd train-planner
npm install
npm start          # 默认 http://localhost:3000
```

Windows 可直接双击 `启动.bat`，macOS / Linux 双击 `启动.command`。

> 首次打开可能等 10~30 秒（服务冷启动），之后秒开。

### 环境变量（可选）

| 变量 | 默认值 | 作用 |
|---|---|---|
| `PORT` | `3000` | 服务端口 |
| `MAX_CONCURRENCY` | `4` | 同时打到 12306 的请求上限 |
| `MIN_REQUEST_INTERVAL` | `150` | 两次请求的最小间隔（ms） |
| `HUB_CONCURRENCY` | `5` | 同时查询几个中转枢纽 |
| `QUERY_CACHE_TTL` | `60000` | 查询缓存时长（ms），设 0 关闭 |
| `CITY_LIMIT` | `8` | 市内出发最多合并几个车站 |
| `COOKIE_EXTRA` | — | 补充 cookie，见下文 |

> 想更快就把 `MIN_REQUEST_INTERVAL` 调小、`MAX_CONCURRENCY` 调大；但**代价是更容易被 12306 限流**。

## 🌐 部署

### Vercel（推荐，免费）

1. 导入本仓库到 Vercel
2. Framework 选 `Other`，其余保持默认（`vercel.json` 已配好 `@vercel/node` + 静态资源路由）
3. 部署完成后在 **Settings → Domains** 绑定自己的域名

> `server.js` 末尾有 `module.exports = app`，可直接作为 Serverless Function 运行。

### 🌏 国内访问：套一层 Cloudflare（免费，实测可用）

Vercel 的 IP 在国内移动网络上经常被重置。实测**绑定自有域名 + Cloudflare 代理**后可以正常访问，成本 0。

**核心思路**：让用户连接 Cloudflare 的 IP（国内可达），由 CF 回源到 Vercel。

1. Cloudflare 添加站点 `你的域名`，选 **Free** 套餐
2. 把 CF 给的两个 NS 填到域名服务商的「DNS 服务器」里（完成解析权移交）
3. CF → **DNS** → 添加 `CNAME @ → cname.vercel-dns.com`，代理状态点成**橙色云朵**
4. CF → **SSL/TLS** → 加密模式选 **Full**
5. 等 Universal SSL 证书签发（**通常 10 分钟~24 小时**，期间 HTTPS 会握手失败，属正常）

**三个实测踩过的坑**：

| 坑 | 现象 | 说明 |
|---|---|---|
| 证书未签发 | `alert handshake failure` / 证书错误 | 等 Universal SSL 变 Active，HTTP 80 此时已通 |
| IPv6 无法关闭 | 新版账户 IPv6 兼容开关是灰的 | CF 已强制开启，手机若 IPv6 优先可能不通 |
| DNS 缓存滞后 | 电脑能开、手机打不开 | 旧 NS 的 TTL 是 86400，运营商最长缓存 24 小时；换无痕窗口或改用公共 DNS 可立刻验证 |

> 判断依据：浏览器**无痕窗口能打开**就说明服务端和证书都没问题，剩余只是本地/运营商缓存。

### 自建服务器（国内推荐）

国内服务器不仅访问快，查询 12306 也快几个数量级（中转 20 个枢纽：Vercel 约 51 秒，国内约 12 秒）。

```bash
git clone https://github.com/clq12/train-planner.git && cd train-planner
npm install --omit=dev
PORT=3000 nohup node server.js > app.log 2>&1 &
```

建议前面挂 Nginx 反代并开启 HTTPS。**注意**：中转查询用的是 NDJSON 流式响应，Nginx 必须关闭缓冲，否则页面会卡住不刷新：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_buffering off;
    proxy_cache off;
    proxy_set_header Host $host;
    proxy_read_timeout 300s;
}
```

## 🔌 接口

| 接口 | 说明 |
|---|---|
| `GET /api/stations` | 全部车站（含城市归属），缓存 1 小时 |
| `GET /api/city-stations?from=VRH` | 该站所属地级市下的所有车站 |
| `GET /api/ticket?from=&to=&date=` | 余票查询，`&cityFrom=1` 合并同城车站 |
| `GET /api/transfer?from=&to=&date=` | 中转换乘（NDJSON 流式返回），`&allHubs=1` 查全部枢纽 |
| `GET /api/schedule?trainNo=&date=&fromCode=&toCode=` | 某趟车在某区间的时刻表 |
| `GET /api/schedule-by-no?trainNo=&date=` | 按车次号反查全程时刻表 |
| `GET /api/cookie-status` | 当前生效的 cookie 名（不返回值） |
| `GET /api/health` | 健康检查 |

## 📐 技术栈与结构

- **前端**：单文件 HTML + CSS + 原生 JS，零框架、零构建
- **后端**：Node.js + Express，作为 12306 的代理并做并发控制
- **数据源**：12306 官方公开接口

```
train-planner/
├── server.js               # Express 后端：12306 代理、并发池、缓存、换乘算法
├── public/
│   └── index.html          # 前端单页（HTML + CSS + JS 全在一个文件）
├── vercel.json             # Vercel 部署配置
├── render.json             # Render 部署配置
├── 启动.bat / 启动.command  # 一键启动脚本
└── package.json
```

### 性能设计

12306 查询是 IO 密集型，瓶颈在「等响应」而不是「算」，所以整套优化都围绕**减少等待**：

| 手段 | 效果 |
|---|---|
| 信号量并发池（4 个在途 + 150ms 最小间隔） | 真正的限流；原实现只判断时间差不排队，突发时会一起打出去 |
| 前端 `mapLimit(4)` 工作池 | 逐车次查询从串行改并发，70 个请求 35.5s → 6.7s |
| 60 秒查询缓存 | 多策略重复查同一区间近乎零耗时 |
| 同城枢纽去重 | 济南西/济南/济南东 只查一个，中转请求量降约 1/3 |
| 302 全局冷却 + 快速失败 | 被限流时立刻返回 429，不再排队干等 |
| 单站两段并发 | 同车换乘的两段余票同时查，省一个往返 |

> 实测：中转换乘 20 个枢纽，24.4 秒 → 12.3 秒；策略内 70 个请求，35.5 秒 → 6.7 秒。

## 🍪 Cookie 说明

余票查询**不需要登录**。程序启动后自动访问 `/otn/leftTicket/init`，从 `Set-Cookie` 拿到 `JSESSIONID`、`SF_cookie_2`、`BIGipServerotn`，之后每个请求自动带上，3 分钟刷新一次，遇到 302 立即重新获取。

如果 12306 频繁返回 302，可以补充自己的 cookie（**只补缺、不覆盖**自动获取的会话 cookie）：

| 方式 | 做法 |
|---|---|
| `cookie.txt`（推荐） | 项目根目录新建，一行写完，如 `RAIL_DEVICEID=xxx; RAIL_EXPIRATION=1799...`，保存即生效，无需重启 |
| 环境变量 | `COOKIE_EXTRA="RAIL_DEVICEID=xxx; RAIL_EXPIRATION=1799..."` |

> `cookie.txt` 已在 `.gitignore` 中。查看当前生效的 cookie：`GET /api/cookie-status`（只返回名字）。
> 同名站点的 cookie 含登录态，**不要外传**。

## 📝 数据来源与合规

- 所有数据来自 12306 官方公开接口，实时查询、不落库
- 票价按 `yp_ex_str` 字段解析，为实际票价；拿不到时回退为估算并标注 `≈`
- **本工具只做查询与方案建议，不代购、不抢票、不代下单**
- 「买长乘短」「买短乘长」等方案需自行在 12306 官方渠道购票
- 请控制查询频率；因高频访问导致的限流（302）属正常现象

## ⚠️ 已知限制

- 12306 有风控，短时间大量查询会被限流（返回 302），会触发全局冷却，等几分钟即可
- 部分车次 12306 不返回票价，这类车次显示估算价（带 `≈`）
- 中转只查固定枢纽清单（省会 / 主要枢纽），不是全网所有可能的换乘点
- Vercel 部署时 `*.vercel.app` 域名在国内常被阻断，需绑定自己的域名

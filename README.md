# 🚄 票路 · 车票路径规划器

> **直达没票？换条路走。**
>
> 基于 12306 实时数据的多策略购票方案规划工具 —— 帮你把「买长乘短 / 买短乘长 / 中转换乘 / 同车换乘」这些野路子，一次性算清楚。

**在线体验**：<https://piaolu.cc.cd>　·　**管理设置**：<https://piaolu.cc.cd/admin>

---

## 这个工具解决什么问题

12306 只告诉你「这趟车有没有票」，但没告诉你：

- 买到**更远的站**，反而有票，中途下车就行
- 目标区间没票，但**分成两段买**能走
- 直达没票，**换个枢纽换乘**能到
- 同一趟车**拆成两段**买（中途不下车），也许两段都有票

这个工具把这些思路全部自动化：一次查询，同时给出直达、候补、买长乘短、中转换乘、同车换乘、买短乘长六种方案，并标出**哪个最便宜、哪个最快、哪个到得最早**。

## ✨ 核心能力

### 六种购票策略

| 策略 | 思路 | 自动化程度 |
|---|---|---|
| 🚄 直达（有票） | 直接查目标区间 | 自动 |
| ⏳ 直达（可候补） | 无票车次可提交候补 | 自动识别 |
| 🎯 买长乘短 | 买到更远站，在目标站提前下车 | 自动枚举更远站点并查余票 |
| 🔄 中转换乘 | 经枢纽站换乘，两段自由搭配 | 自动查 20 个常见枢纽 + 出发/到达同城站；先验证后程有车，再校验站点与换乘时间 |
| ✂️ 同车换乘 | 同一趟车分段购票，中途不下车 | 自动枚举中间站并校验两段余票 |
| 📝 买短乘长 | 先买短途票上车，再补票到终点 | 自动枚举中间站 |

> 💡 **小站出发也能算**：中转换乘会把**出发地、目的地同城（同地级市）的其他车站**一并纳入枢纽，而且先验证「枢纽→目的地」有没有直达车、有才保留。所以「宁海→项城」能算出「宁海 → 宁波 → 项城」这种先到本市枢纽再走干线的方案，而不只是绕到南京、合肥这类远距离大枢纽。

### 🧭 换乘站名按实际车次显示

12306 查「成都东」时，返回的车次不一定真的停成都东 —— 可能到「成都龙泉驿」、从「成都西」发车，终点甚至可能是「松潘」而不是「黄龙九寨」。票路不会拿枢纽名糊弄过去：

- 方案标题和两列列名列出这块方案里**所有真实的换乘站**，不再统一写一个站名
- 每一趟车都单独标出自己的真实起终点，跟多数车次不同的站会带 `⚠` 高亮
- 选中组合后，汇总条给出两段的真实站名、换乘间隔、总耗时和总花费
- 需要跨站换乘时会明确提示「需跨站换乘：A → B」，并且只保留换乘间隔至少 90 分钟的组合；不同城市的两段不会拼在一起

> 跨站方案仍然保留、也参与「价格最低」比较。价格优先时不必为了省事丢掉便宜车，只是把要多跑一趟这件事摆到明面上。

### 🎯 指定中转站（搜索框下方）

想固定经某个站走，就在搜索框下方输入站名 —— 支持中文、拼音、简拼、车站代码的下拉联想。查询时只算「出发地 → 这个站 → 目的地」怎么走：

- 指定的站会在方案标题上打 `📌 指定` 标记，两段车次照常自由搭配
- 如果这个站本身没有合适的车，会自动尝试它**同城的其他车站**（比如指定「成都东」，顺带看成都 / 成都南 / 成都西），并在提示条里说明用的是备选
- 主站算得出方案时只显示主站一张卡片，不会用几张几乎一样的同城卡片刷屏
- 站名写错会直接提示「未找到指定中转站」，不会静默查出一堆无关枢纽
- 点「✕ 清除」或留空，就恢复自动找 20 个常见枢纽

> 指定中转站时「使用 20 个常见枢纽」开关会自动置灰，因为它对这次查询不再生效。

### 💰 真实票价，不是估算

票价直接来自 12306 的实时数据，不是按里程或倍率估出来的。

- 商务座、一等座、二等座、软卧、硬卧、硬座、无座，每种席别都显示实际价格
- 鼠标悬停，能看到这趟车所有席别的票价
- 实在拿不到票价的车次，会退回估算并标上 `≈`，不冒充真实价
- 实测京沪线 54 趟车，**全部显示真实票价**

### 🏙️ 市内出发：一个城市，所有车站一起查

选了「温州南」，温州、温州北、瑞安、乐清、苍南…… 这个城市的所有车站会一起查。
不用再担心"这个站没票，隔壁站其实有票"。

温州南 → 上海虹桥 实测：

| 查询方式 | 车次 |
|---|---|
| 只查温州南 | 101 趟 |
| 开启市内出发 | **150 趟** |

多出来的 49 趟来自苍南、平阳、瑞安、雁荡山、乐清 —— 不开这个选项，你根本看不到这些票。

全国城市都适用。北京、广州、成都这类高铁站多的城市收益最大（北京 65 个站、广州 45 个、成都 36 个）。

- 大站优先，最多合并 8 个车站
- 只作用于直达列表；买长乘短、同车换乘、买短乘长 查的是特定车次，不受影响，也不会因此变慢

### 🌙 跨日换乘

第二段默认往后查出发日 / 次日 / 第三日三天，在 `/admin` 里可以调到 2~7 天。同一趟车连着几天都会出现，时刻相同、日期不同，所以发车时间前会标出 **`+1` / `+2` / `+3`…** 徽标，一眼分清是哪天走。

发车时间**前**的 `+N` 是「第几天发车」，到达时间**后**的 `+N` 是「第几天到达」，两者都相对**整个行程的出发日**算，可以直接对照。

第一段跨夜到达也会标：K1256 是 `23:50 → 09:04 +2`，意思是第三天上午才到，不是「第二天一早」。第二段如果本身隔了一天才发车、车程又过了一夜，两个偏移会叠加 —— `+1 15:05 → 00:25 +2` 就是次日下午出发、第三天凌晨到，不会再出现「发车 +1、到达也 +1」这种看着像第二天的写法。

```
Z218   +0  03:34 → 16:42
Z218   +1  03:34 → 16:42
Z218   +2  03:34 → 16:42
K1256  23:50 → 09:04 +2
D197  +1  15:05 → 00:25 +2
```

选中两段车次后，汇总条还会直接写「第 3 天到」。换乘间隔和总耗时都会把跨日算进去 —— 第一段跨夜、第二段隔一两天才走，也不会显示成负数或 0 分钟。在 `/admin` 放宽等待上限后，价格优先时可以一直等到更便宜的后程。

### 🏅 中转最优标签（可点击）

每个枢纽标题旁自动标注，且**点击即选中对应车次**：

```
🔄 经 天津南 / 天津西 换乘  [价格最低] [到达最快]    9趟前程 + 24趟后程
🔄 经 南京南 换乘         [时间最短]                52趟前程 + 20趟后程
```

| 标签 | 意思 |
|---|---|
| 💰 价格最低 | 这条换乘线路，两段加起来最便宜 |
| ⏱️ 时间最短 | 从上车到下车，全程耗时最短（含换乘等待） |
| 🏁 到达最快 | 到达时间最早，跨日也算进去 |

- 只统计**两段能衔接、且都有票**的组合，不会把「最低价」标在一张买不到的票上
- 第一段里接不上任何第二段的车次会标「无衔接」并淡化，不参与比较
- 跨站换乘组合同样参与评选，选中后汇总条会提示需要换站
- 点一下标签，对应的两段车次自动选中，底部直接显示真实站名、总耗时、总花费
- 三个标签可以来回切换比较，当前查看的那个会高亮

### 📊 排序与筛选

每个策略卡片独立排序、独立筛选：

- 排序：出发时间 / 到达时间 / 耗时 / 价格（再点一次反向）
- 筛选：出发时间范围、到达时间范围，支持跨零点（22:00 ~ 06:00）
- 六种策略类型全部支持（中转换乘按「枢纽块最优组合」排序，同车换乘按车次排序）

### 🔎 阅读设置（右上角）

字号可在 **16~24px** 之间无级调节（每格 1px，默认 18px），拖动即时生效，刷新后保留。

旁边还有 **老年人模式**：开启后字号直接拉到 26px（超出滑块上限），并同步放大行距、间距、勾选框，加深文字对比度，车次列表改为单列、隐藏时间筛选等次要元素。开启时字号滑块会变灰锁定，关闭后自动回到你之前设定的字号。

### ▤ 单列 / 双列（左上角）

车次列表可在单列（默认）与双列之间切换，选择会被记住：

- **单列**：整列 1080px，信息舒展，适合慢慢看
- **双列**：容器放宽到 1460px，一屏看两倍车次，适合快速筛选

窄屏（≤899px）与老年人模式下自动锁定单列。

### ✈️ 航班与火车出行日程

日程页已融合进主站：点顶部「出行日程」或车次卡片上的「比对出行日程」，会在当前页面弹出日程浮层，不再整页跳转。搜索结果、当前标签和筛选状态都保留；浮层顶部有「关闭并返回搜索结果」，日程页里的返回按钮和 Esc 键同样能关闭。嵌入模式用 `?embed=1` 标识，样式会收紧留白以适配浮层。

1. 从首页点「出行日程 · 火车与航班」，填写出发地、到达地、日期和时分。所有时间统一使用北京时间，出发和到达日期默认北京时间的今天，时分自行填写；跨日行程需修改到达日期。
2. 回到首页查火车，在直达车次上点「比对出行日程」。页面会先显示候选车次与当前日程的间隔，你可以确认加入，也可以丢弃候选继续找。
3. 按实际需要调整预留时间：下一段为航班默认 120 分钟，航班落地后接火车或地面交通默认 90 分钟，其他情况接火车默认 20 分钟。不同车站、机场或航站楼之间，可手动加一段地面接驳。间隔达到设置值不代表一定赶得上：请另外核对路况、值机、安检、行李及最晚登机时间。

火车以北京时间计算，首页的今天、默认明天和查询上限也按北京时间日历生成，与浏览器时区无关；候选车次沿用本次查询的出发日期。跨日到达用实际运行时长推算；手动添加的航班、火车和地面接驳统一按北京时间保存，页面不再展示时差输入框或数字时差标记。已有其他时区的历史行程会按原实际时刻换算为北京时间显示，编辑保存也不会改变实际时刻。日程按此前最晚结束的行程比对接驳，并保留各段直接时间冲突；不同地点在冲突、预留不足和达到预留时都会提醒核对地面接驳。已保存日程只保存在当前浏览器，不会上传。

航班地点提供 43 个常用内地机场的本地建议，支持 IATA 代码（不区分大小写）、中文名及简称、拼音和首字母，例如 `pek`、`bjsd`、`sd`、`首都`。输入 `BJ` 或北京会列出首都和大兴，等待选择；建议显示机场代码和名称。火车地点按需加载 `/api/stations`，支持站名、三字代码、拼音和简拼。上下方向键移动，Enter 选择当前建议，Escape 关闭；也可点击或触摸选择。打开列表不会自动确认首项。所有交通方式均允许自由手填，包括国际机场和未列入目录的地点；车站加载失败或机场目录脚本不可用时仍可手录。地面接驳只使用自由输入。

日程页已移除航班报价查询，无需航班供应商配置。旧 `/api/domestic-flights/status` 和 `/api/domestic-flights/search` 固定返回 HTTP 410 与 `FEATURE_REMOVED`，不会联系航班供应商。既有浏览器日程（`piaolu_itinerary_v1`）及历史导入航段的航司、航站楼、经停详情继续保留。

分段行程和当地时间的交互参考了 [TREK 的交通行程](https://github.com/liketrek/TREK/blob/main/wiki/Transport-Flights-Trains-Cars.md)，未复制 TREK 源码。

### 🗺️ 全国列车时刻地图（铁路全景 + 余票.info）

首页第四个标签「实时地图」内嵌 `/live-map.html`，也可直接全屏打开。点位数据只用两个来源：

| 来源 | 融合进来的能力 |
|---|---|
| [铁路全景](https://linkboyx.github.io/railway-panorama/) | 14096 趟车的图定时刻、5 万余条线路边、3305 个车站。服务端 `lib/rail-model.js` 解码它的紧凑数据，按任意时刻算出在途列车的位置、方向、速度、当前/下一站 |
| [余票.info](https://www.yupiao.info/) | 「余票回放」模式：把当前视野、日期、时刻（以及选中车次）写进它的 URL hash，用另一套按 12306 时刻表推算的地图对照查看 |

**地图主题**：标准（高德街道图）、卫星（高德影像 + 注记）、夜色（瓦片反色）、线网（无底图，只画铁路线）。四种主题共用同一套 GCJ-02 坐标转换，切换不影响点位。

**时间控制**：日期 + 0:00–23:59 滑块、「▶ 播放」逐分钟推演（速度 0.5× / 1× / 2× / 4× / 8× 可调，列车位置逐帧插值平滑移动）、「现在」回到当前时刻并每 30 秒跟随刷新。URL hash 同时兼容 `#map=10.52/25.6106/119.3363` 和 `#time=08:00&@lat,lon,z`，打开链接即可还原视野与时刻。

**从搜索结果直达**：车次卡片和时刻表弹窗里都有「🗺️ 地图线路」按钮，点击后跳到实时地图标签，地图自动选中该车、画出全程线路并把视野缩放到整条线。深链格式是 `/live-map.html#map=4/35.5/104&time=07:11&date=2026-11-24&train=G1`，车次不在当前时刻运行也能看线路。

**点击列车**：参照余票站的交互，详情面板分「时刻表 / 运行图」两页——时刻表标出到发与停时、当前站和下一站，点站名可跳到该时刻并定位；运行图是站序—时间的折线图并带当前时刻标线。地图上同时高亮该车全程线路和所有停站，可选「全程视野」，选中车头按方位角旋转。余票回放按钮可往返切换，回切时地图视野保持不变。

实现要点：服务端一次性加载约 11 MB 原始数据，单次算 3600 趟在途列车约 70 ms，浏览器只收到几千个轻量点位；列车用 Canvas 渲染，车次号标签只在 z≥7 且限量 220 个。WGS-84 统一转 GCJ-02 后叠加高德瓦片。列车位置是按图定时刻推算的结果，非 12306 官方实时数据，仅作参考。

## 🚀 快速开始

### 在线访问

直接打开 <https://piaolu.cc.cd>（Vercel 免费版首次打开可能等 10~30 秒冷启动，之后秒开）。

### 本地运行

```bash
git clone https://github.com/clq12/train-planner.git
cd train-planner
npm install
npm start          # 默认 http://localhost:3000
```

也可以用容器跑，仓库自带 `Dockerfile`：

```bash
docker build -t piaolu .
docker run -p 3000:3000 piaolu
```

### 环境变量（可选）

| 变量 | 默认值 | 作用 |
|---|---|---|
| `PORT` | `3000` | 服务端口 |
| `MAX_CONCURRENCY` | `4` | 同时打到 12306 的请求上限 |
| `MIN_REQUEST_INTERVAL` | `150` | 两次请求的最小间隔（ms） |
| `HUB_CONCURRENCY` | `5` | 同时查询几个中转枢纽 |
| `QUERY_CACHE_TTL` | `60000` | 查询缓存时长（ms），设 0 关闭 |
| `CITY_LIMIT` | `8` | 市内出发最多合并几个车站 |
| `LEG2_DAYS` | `3` | 中转第二段往后查几天（1~7；管理页滑块 2~7） |
| `MAX_TRANSFER_GAP_MIN` | `2160` | 两段之间最长等待（分钟，默认 36 小时） |
| `COOKIE_EXTRA` | — | 补充 cookie，见下文 |

> 想更快就把 `MIN_REQUEST_INTERVAL` 调小、`MAX_CONCURRENCY` 调大；但**代价是更容易被 12306 限流**。
>
> `LEG2_DAYS` / `MAX_TRANSFER_GAP_MIN` 是服务端全局默认值；访问 `/admin` 可在当前浏览器上临时覆盖，无需改环境变量。

## ⚙️ 管理设置（`/admin`）

访问 `https://你的域名/admin` 可以调整中转检索参数：

| 设置 | 范围 | 默认 | 说明 |
|---|---|---|---|
| 第二段检索天数 | 2~7 天 | 3 天 | 往后查几天，越多越容易找到便宜慢车，但更慢 |
| 换乘等待上限 | 1~72 小时 | 36 小时 | 放宽后可"等到第二天再走"换更便宜的后程 |

**生效范围**：本站部署在 Vercel（无状态），服务端无法持久化设置，因此参数存在**当前浏览器的 localStorage**，查询时随请求发送（`&days=3&gapH=36`）。换设备需重设；想改全局默认值请设置环境变量 `LEG2_DAYS`、`MAX_TRANSFER_GAP_MIN`。如果之前保存过旧参数，浏览器会继续沿用旧值，点页面上的「恢复默认」即可。

三种推荐组合：

- **速度优先**：2 天 / 12 小时（最快，方案最少）
- **均衡（默认）**：3 天 / 36 小时
- **价格优先**：6 天 / 48 小时（愿意多等，换取更便宜的后程）

> 天数越多、等待上限越大，向 12306 发的请求也越多，遇到 302 限流的概率明显上升。另外长时间普速车（如 K1256）是 **+2 天** 才到，天数调到 2 天时它会显示「无衔接」，默认 3 天才能接上。

### 🌏 国内访问：套一层 Cloudflare（免费，实测可用）

Vercel 的 IP 在国内移动网络上经常被重置。实测**绑定自有域名 + Cloudflare 代理**后可以正常访问，成本 0。

**核心思路**：让用户连接 Cloudflare 的 IP（国内可达），由 CF 回源到 Vercel。

1. Cloudflare 添加站点 `你的域名`，选 **Free** 套餐
2. 把 CF 给的两个 NS 填到域名服务商的「DNS 服务器」里（完成解析权移交）
3. CF → **DNS** → 添加 `CNAME @ → cname.vercel-dns.com`，代理状态点成**橙色云朵**
4. CF → **SSL/TLS** → 加密模式选 **Full**
5. 等 Universal SSL 证书签发（**通常 10 分钟~24 小时**，期间 HTTPS 会握手失败，属正常）

**三个实测踩过的坑**：

| 坑 | 现象 | 说明 |
|---|---|---|
| 证书未签发 | `alert handshake failure` / 证书错误 | 等 Universal SSL 变 Active，HTTP 80 此时已通 |
| IPv6 无法关闭 | 新版账户 IPv6 兼容开关是灰的 | CF 已强制开启，手机若 IPv6 优先可能不通 |
| DNS 缓存滞后 | 电脑能开、手机打不开 | 旧 NS 的 TTL 是 86400，运营商最长缓存 24 小时；换无痕窗口或改用公共 DNS 可立刻验证 |

> 判断依据：浏览器**无痕窗口能打开**就说明服务端和证书都没问题，剩余只是本地/运营商缓存。

国内服务器不仅访问快，查询 12306 也快几个数量级（中转 20 个枢纽：Vercel 约 51 秒，国内约 12 秒）。

### 性能设计

12306 查询是 IO 密集型，瓶颈在「等响应」而不是「算」，所以整套优化都围绕**减少等待**：

| 手段 | 效果 |
|---|---|
| 信号量并发池（4 个在途 + 150ms 最小间隔） | 真正的限流；原实现只判断时间差不排队，突发时会一起打出去 |
| 前端 `mapLimit(4)` 工作池 | 逐车次查询从串行改并发，70 个请求 35.5s → 6.7s |
| 60 秒查询缓存 | 多策略重复查同一区间近乎零耗时 |
| 同城枢纽去重 | 济南西/济南/济南东 只查一个，中转请求量降约 1/3 |
| 302 全局冷却 + 快速失败 | 被限流时立刻返回 429，不再排队干等 |
| 单站两段并发 | 同车换乘的两段余票同时查，省一个往返 |

> 实测：中转换乘 20 个枢纽，24.4 秒 → 12.3 秒；策略内 70 个请求，35.5 秒 → 6.7 秒。

## 🍪 Cookie 说明

余票查询**不需要登录**。程序启动后自动访问 `/otn/leftTicket/init`，从 `Set-Cookie` 拿到 `JSESSIONID`、`SF_cookie_2`、`BIGipServerotn`，之后每个请求自动带上，3 分钟刷新一次，遇到 302 立即重新获取。

如果 12306 频繁返回 302，可以补充自己的 cookie（**只补缺、不覆盖**自动获取的会话 cookie）：

| 方式 | 做法 |
|---|---|
| `cookie.txt`（推荐） | 项目根目录新建，一行写完，如 `RAIL_DEVICEID=xxx; RAIL_EXPIRATION=1799...`，保存即生效，无需重启 |
| 环境变量 | `COOKIE_EXTRA="RAIL_DEVICEID=xxx; RAIL_EXPIRATION=1799..."` |

> `cookie.txt` 已在 `.gitignore` 中。查看当前生效的 cookie：`GET /api/cookie-status`（只返回名字）。
> 同名站点的 cookie 含登录态，**不要外传**。

## 📝 数据来源与合规

- 所有数据来自 12306 官方公开接口，实时查询、不落库
- 票价显示 12306 的实际售价；个别车次拿不到价格时会标注 `≈` 估算，不冒充真实价
- **本工具只做查询与方案建议，不代购、不抢票、不代下单**
- 「买长乘短」「买短乘长」等方案需自行在 12306 官方渠道购票
- 请控制查询频率；因高频访问导致的限流（302）属正常现象

## ⚠️ 已知限制

- 12306 有风控，短时间大量查询会被限流（返回 302），会触发全局冷却，等几分钟即可
- 部分车次 12306 不返回票价，这类车次显示估算价（带 `≈`）
- 中转候选是 20 个常见枢纽 + 出发地/目的地的同城站，不是全网所有可能的换乘点
- 中转换乘只支持**两段**（出发 → 枢纽 → 到达），不支持三段及以上的全量组合
- 12306 会把同城站一起返回，所以搜「黄龙九寨」也可能出现终到「松潘」的车；购票前请核对每行车次列出的真实站名
- 同城不同站的组合会列出并标注「需跨站换乘」，市内交通时间需自行判断；不同城市的两段不会拼在一起
- Vercel 部署时 `*.vercel.app` 域名在国内常被阻断，需绑定自己的域名

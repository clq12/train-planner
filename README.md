# 🚂 车票路径规划器 (Train Ticket Route Planner)

> 基于12306实时数据的多策略购票方案规划工具

## ✨ 核心功能

### 🔥 接入12306真实数据
- **实时余票查询** — 直连12306 API，查询真实车次和余票信息
- **列车时刻表** — 查看任意车次（如G2、D31）的完整停靠站时刻表
- **3365个车站** — 覆盖全国所有火车站
- **车次搜索** — 输入G2、D31等车次号直接查询时刻表

### 🧠 6种购票策略

| 策略 | 说明 | 自动化 |
|------|------|--------|
| 🚄 **直达（有票）** | 直接查询目标区间余票 | ✅ 自动查询 |
| ⏳ **直达（可候补）** | 无票车次可提交候补 | ✅ 自动识别 |
| 🎯 **买长乘短** | 买到更远站点，在目标站提前下车 | ✅ 自动查询更远站点余票 |
| 🔄 **中转换乘** | 经大型枢纽站换乘，分段展示可自由搭配 | ✅ 自动查询 + 智能兼容性筛选 |
| ✂️ **同车换乘** | 同一趟车在中间站拆分购票，无需下车换乘 | ✅ 自动查询分段方案 |
| 📝 **买短乘长** | 先买短途票上车再补票 | ✅ 自动查询可行方案 |

### 📊 排序与筛选

每个策略卡片均支持**独立的**排序和筛选：

**排序方式：**
- 🕐 出发时间（升序/降序）
- 🕕 到达时间（升序/降序）
- ⏱️ 耗时（升序/降序）
- 💰 预估价格（升序/降序）
- 🔄 换乘时间（仅换乘/分段策略）

**筛选条件：**
- 出发时间范围（如 08:00 ~ 12:00）
- 到达时间范围（如 14:00 ~ 18:00）
- 支持跨午夜筛选（如 22:00 ~ 06:00）
- 筛选框可选填，不填则不限制

### 💰 真实票价显示

直接从12306 API的 `yp_ex_str` 字段解析**真实票价**，而非估算
（注：旧的 `yp_info` 字段已改为加密串，不再包含票价）：

- ✅ 有真实票价时显示 `¥553起`（无 ≈ 前缀）
- ⚠️ 无真实票价时回退到估算，显示 `≈¥553起`
- 鼠标悬停可查看所有可用席别的具体价格
- 覆盖所有席别：商务座、一等座、二等座、软卧、硬卧、硬座、无座

### 🔄 换乘交互体验

**中转换乘 & 同车换乘** 均采用左右双列布局：
- 左侧显示第一段车次，右侧显示第二段车次
- 点击左侧车次，自动筛选可衔接的右侧车次
- 选中组合后底部显示方案汇总：总耗时、总花费、换乘间隔
- 中转换乘支持跨日期换乘（自动查询次日车次）

### 📈 实时进度提示

查询过程中进度条平滑更新，实时显示当前查询状态：
- 直达查询：`正在查询12306直达车次...`
- 买长乘短：`正在查询买长乘短 3/10（G1234）...`
- 中转换乘：`正在查询中转站 济南西（5/20，已找到3个方案）...`
- 同车换乘：`正在查询同车分段 2/10（D5678）...`
- 买短乘长：`正在查询买短乘长 1/8（G9012）...`

## 📐 技术栈

- **前端**: 纯 HTML + CSS + JavaScript（零框架依赖）
- **后端**: Node.js + Express（12306 API代理）
- **数据源**: 12306 官方API
  - 车站数据: `/otn/resources/js/framework/station_name.js`
  - 余票查询: `/otn/leftTicket/queryG`
  - 列车时刻: `/otn/czxx/queryByTrainNo`
  - 换乘查询: 多段余票查询 + 时间匹配算法

## 🍪 Cookie 说明

余票查询**不需要登录**。程序启动后会自动访问 `12306/otn/leftTicket/init`，从 `Set-Cookie` 里拿到 `JSESSIONID`、`SF_cookie_2`、`BIGipServerotn` 三个 cookie，之后每个请求自动带上，3 分钟自动刷新一次，遇到 302 会立即重新获取。

**如果 12306 频繁返回 302，可以补充自己的 cookie**（只补缺、不覆盖程序自动拿到的会话 cookie）：

| 方式 | 做法 |
|---|---|
| cookie.txt（推荐） | 项目根目录新建 `cookie.txt`，一行写完，例如 `RAIL_DEVICEID=xxx; RAIL_EXPIRATION=1799...`，保存后下一次请求自动生效，不用重启 |
| 环境变量 | 启动前设置 `COOKIE_EXTRA="RAIL_DEVICEID=xxx; RAIL_EXPIRATION=1799..."` |

> `cookie.txt` 已在 `.gitignore` 里，不会被提交。
> 查看当前生效了哪些 cookie：访问 `http://localhost:3000/api/cookie-status`（只返回名字，不返回值）。

## 📝 数据说明

- 余票数据来自12306官网API，实时更新
- **票价数据**：从12306返回的 `yp_ex_str` 字段解析，为实际票价（编码：席别1位+整数元4位+角1位+标志1位+余票3位）
- 本工具仅提供查询和策略建议，不进行实际购票
- "买长乘短"、"买短乘长"等策略需要在12306官网/APP完成购票

### v1.3.10 (2026-11-02)

- **修复开启「市内出发」后策略查询变慢 8 倍**：`cityFrom=1` 之前被误加到买长乘短/同车换乘/买短乘长的余票请求上，每次查询扇出到最多 8 个同城站。这些策略查的是"特定车次"，同城扩张没有意义，已全部移除（只保留主列表查询使用）
- 策略试算站数设上限：同车分段/买短乘长每趟车最多试 4 个中间站，买长乘短最多试 4 个更远站
- 服务端：12306 限流期间直接返回 429（不再排队干等）；`/api/ticket` 重试次数 4 → 2（每次重试都要刷 cookie）

### v1.3.9 (2026-11-02)

- **中转枢纽标题新增三个最优标签**：「价格最低」「时间最短」「到达最快」，根据该枢纽"能接上的组合"自动打标（一格可同时命中多个）
- 判定口径：只在两段**都有票**的组合里比；整个枢纽都无票时才退回全部车次比较
- 价格取两段最低价之和；耗时含换乘等待；到达时间按 dayOffset 换算成绝对分钟（跨日不会算错）
- 票价缺失（返回 0）的组合不参与价格比较，避免被误标"价格最低"

### v1.3.8 (2026-11-02)

- 新增 `stratPlanTransfer()` / `stratPlanSegments()`：中转换乘按枢纽块内"最优第一段"排序（价格取前后两段之和），同车换乘按车次时刻排序

- 渲染顺序与数据索引解耦：`hubId` / `segHubId` 里保留原始索引，点选回调仍能正确取到数据

### v1.3.5 (2026-10-30)

- **修复票价解析**：12306 已把票价从 `yp_info` 移到 `yp_ex_str`，原解析逻辑失效（多数车次取不到票价）。现按新编码解析（席别1位 + 整数元4位 + 角1位 + 标志1位 + 余票3位），实测京沪线覆盖率 **5/54 → 54/54**
- **服务端并发池**：`throttledFetch` 原来是"距上次请求不足 300ms 就等"的开关，同批请求会一起跳过等待、一起打 12306；改为「信号量 + 最小间隔」，真正限制在途请求数
- **中转换乘并发**：枢纽查询由串行改为并发，并去掉同城重复枢纽（济南西/济南/济南东 只查一个）、排除与起终站同城的枢纽。北京→上海 实测 **24.4s → 7.2s**
- **前端并发**：买长乘短 / 同车换乘 / 买短乘长 三条策略的逐车次查询改为受限并发（默认 4 个），实测 70 个请求 **35.5s → 6.7s**
- **查询缓存**：同一「出发站+到达站+日期」60 秒内直接复用结果，多策略重复查同一区间时几乎零耗时
- **限流退避**：12306 返回 302 时触发全局冷却（默认 3 秒）并自动刷新 cookie，避免越撞越死
- **可调参数**（环境变量）：`MAX_CONCURRENCY`（在途请求上限，默认 4）、`MIN_REQUEST_INTERVAL`（请求最小间隔 ms，默认 150）、`HUB_CONCURRENCY`（同时查几个中转枢纽，默认 5）、`QUERY_CACHE_TTL`（缓存毫秒数，默认 60000，设 0 关闭）
